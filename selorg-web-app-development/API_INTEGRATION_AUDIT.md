## Authentication

- Bearer JWT on every protected call; verified that each protected route 401s without a token.
- Token stored in cookie `selorg_token` + localStorage, cleared on 401 and logout.
- `/auth/send-otp` returning 200 does **not** prove an SMS was sent — read `data.deliveryStatus`
  (`sent` / `failed` / `pending`). The fixed test mobile/OTP path is non-prod only
  (`allowFixedTestOtp`) and bypasses the provider entirely.

## Externally dependent paths

Both were live-tested rather than left blocked:

- **Worldline / Paynimo.** `session`, `status`, and `abort` are exercised against a real
  transaction id created during the run. `complete` is asserted to **reject an unsigned
  gateway payload** (400), which verifies hash validation; the success branch is the only
  part that still needs merchant credentials.
- **Delivery coverage.** The harness assigns a real seeded dark store (Bengaluru
  coordinates in `dark_stores`) so `store/assign`, `delivery/estimate`, and `delivery/fee`
  all run against a serviceable location.
- **Wallet debit.** The test account's wallet is funded before the run, so
  `POST /orders` with `paymentMethodType: "wallet"` is exercised for real.

## Known non-blocking note

Unknown category/product URLs render the correct "not found" screen but return HTTP 200
instead of 404. The segment's `loading.tsx` opens a Suspense boundary, so Next.js has
already committed the response status by the time the catalog lookup resolves. Removing
those two `loading.tsx` files would restore a true 404 at the cost of the navigation
skeleton on every valid category and product page.
